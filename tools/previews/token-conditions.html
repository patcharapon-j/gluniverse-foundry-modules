Token Condition Directions

Four ways to draw the conditions a token is carrying, all sitting under the same hostile token and the same resource bar so the comparison is honest. Every direction uses the suite's own palette, chamfer and motion vocabulary — the question is not which is prettiest but which one you can read in half a second while you're looking at something else. Hover a scene to see its labelled state; the controls below drive real apply and remove transitions.

Rail

Cut-corner chips down the token's left flank, worst first — the resource bar's materials turned on their side. Nothing touches the artwork.

Crown

A strip on the token's top edge with the chamfer mirrored — the resource bar cuts top-right, this cuts top-left, so the pair reads as one instrument.

ReadsOne horizontal line. Strongest family resemblance to the bar; the whole state of a creature is two stacked rails.

Halo

Beads seated on a ring around the token, worst at twelve o'clock going clockwise, one hard specular travelling the rim. Every application throws a shockwave.

ReadsClock position. The most tactile of the four, and the only one that scales with the creature rather than sitting beside it.

RiskThe real one. Foundry's target reticle, the disposition ring and this suite's own turn marker are already circles at that radius.
D

Ledger

A named spine. No icon has to be learned, no hover is required, and a valued condition prints its number where a number belongs.

ReadsWords. The only direction a new player can use on their first session without asking what a glyph means.
ScalesSix rows, then +N MORE. Height is honest; width is fixed.
RiskWidest by far. On a crowded map it is a second nameplate per creature, and it does not shrink with zoom.

The tone system

PF2e ships no positive/negative flag on a condition — the system knows only the slug. Every direction above therefore routes its identity through one classification of our own, six tones deep, so colour carries meaning before a glyph is ever resolved. This is the part worth arguing with; the geometry is easier to change later.

N carries a counter — the twelve valued conditions, plus a damage formula on persistent damage.

What I need from you

Placement

Flank (A), top edge (B), ring (C) or spine (D). This is the one choice that is hard to reverse — everything else is a setting.

Labels

Icon-only, icon-with-name-on-hover, or always named. D is always named; A and B expand on hover; C shows a name beside the hovered bead.

Tone

Keep the six-tone classification, collapse it to three (bad / sensory / good), or drop colour semantics and let every condition share the accent.

Motion

The hitstop-then-release beat is shared with the resource bar. The ambient loop — C's travelling specular — is the only always-on animation, and it is optional.

Say a letter and I'll build it. Mixing is fine and probably right — “B's placement, D's labels, A's chip” is a complete brief. The shipped version draws in PIXI with a fragment shader like the resource bars do, so the plates get real bevels and the glow is lit rather than painted; this page is DOM, which is why the edges here are a touch flatter than the result would be.

Behind all four: conditions read from actor.conditions.active on the PF2e side, keyed by slug, with the badge value taken from condition.badge — a counter for the twelve valued conditions, a formula for persistent damage. Foundry's own icon layer gets switched off with renderable = false, never visible, because visible is the permission answer and overwriting it is how a hidden creature's state leaks.
